# Voie Libre: context for Claude Code

Read this file and the [index of features](docs/features/README.md) at the start of each session: a feature's brief says why it exists, and its `## Plan` section (only while the work is open) what is left. The detail of each area below is in [docs/implementation.md](docs/implementation.md). Architecture lives in [docs/architecture.md](docs/architecture.md).

## What this is

Open-source (AGPL-3.0) route planner for road/gravel cycling and trail running, as a website and later an Android app (Capacitor). Local first: routes live on the device; sending anything to the server is always the user's choice. At launch the only user is the author.

## Stack (fixed)

- **Front** (`apps/web`): Angular single-page app, no SSR, strict TypeScript, standalone components, signals. MapLibre GL JS used directly. Transloco for i18n at runtime.
- **API** (`apps/api`): Node.js, Fastify, TypeScript. TypeBox schemas with `@fastify/type-provider-typebox`; OpenAPI generated by `@fastify/swagger` (spec on `/openapi.json`, UI on `/docs`). `@fastify/rate-limit` and `@fastify/cors` are registered.
- **Client** (`packages/api-client`): TypeScript types and `openapi-fetch` client generated from `/openapi.json`. Never edit `src/schema.d.ts` or `openapi.json` by hand: run `npm run generate-client`.
- **Map**: MapView (`core/map`) uses MapLibre directly; the basemap is a France PMTiles file served by the `tiles` service with range requests; the map calls no external domain except two optional layers. [Details](docs/implementation.md#map).
- **Relief source**: By default the hillshade reads the public AWS terrain tiles through a `vlterrain://` protocol (`core/map/relief-source.ts`, `RELIEF_SOURCE_KIND`); `local` keeps an own archive. [Details](docs/implementation.md#relief-source).
- **Relief and layers, local source**: The layer switcher (`MapLayers`: relief, ways, route colour plain, surface or grade, imagery), `buildBasemapStyle`, the optional own relief archive (`npm run build-relief`) and the ways suited to the profile (`way-levels.ts`). [Details](docs/implementation.md#relief-and-layers-local-source).
- **Aerial photos**: Opt-in IGN photos (`MapLayers.imagery`, off by default, never cached): the only other external call of the map. [Details](docs/implementation.md#aerial-photos).
- **Failed tiles**: `retryFailedTiles` asks MapLibre again for tiles in error, after a growing delay. [Details](docs/implementation.md#failed-tiles).
- **Planner**: `PlannerStore` holds the state and the pure rules, `RoutePlanner` computes through the generated client (debounce, aborts stale requests), `PlannerMapDriver` draws; map interaction, loops, stops and the translated API errors. [Details](docs/implementation.md#planner).
- **Open route**: A route built by clicks stays open (`PlannerStore.open`): each place goes after the last point until "Finish here" (bubble, tick, phone sheet); "Continue" reopens it; a typed end, a loop or a saved route is closed. [Details](docs/implementation.md#open-route).
- **Direction arrows**: light arrows on the selected route only: an arrow → on the line where it is ridden one way, ⇄ where both ways (`route-direction.ts`, `ARROW_LAYER` and `HARPOON_LAYER` in the MapLibre driver, from zoom 11). [Details](docs/implementation.md#planner).
- **Local edits**: An edit beside the route recomputes a stretch (`local-edit.ts`, `PointEdit`) or the whole route (`shouldComputeInFull`); a live drag is always local. [Details](docs/implementation.md#local-edits).
- **Live drag**: While a marker or the route is dragged the places are paced (`LIVE_DRAG_INTERVAL_MS`) and applied as local edits; the drop is one step of history, Escape puts it all back. [Details](docs/implementation.md#live-drag).
- **Undo and redo**: A stack of 20 `Snapshot`s in `PlannerStore`; undo and redo restore without any request; Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl+Y and buttons. [Details](docs/implementation.md#undo-and-redo).
- **Place search**: `Geocoder` interface with a Photon provider behind `GET /geocode` and `/geocode/reverse` (only the API calls it); `PlaceField` and `PointNamer` on the web side. [Details](docs/implementation.md#place-search).
- **Points on ways**: On Road and Gravel a placed point snaps to the nearest usable way (`snap-to-way.ts`, `way-snapper.ts`); Trail never snaps. [Details](docs/implementation.md#points-on-ways).
- **Profile choice**: `ProfileSelect`: a radio group of sport pictograms, each with a title and a description. [Details](docs/implementation.md#profile-choice).
- **Elevation profile**: `buildProfile` (pure) and `ElevationPanel` under the map: grade bands, selecting a stretch, a cursor shared with the map, zoom buttons. [Details](docs/implementation.md#elevation-profile).
- **Surface of the route**: `RouteResult.surfaces` (one character per segment: paved, cycleway, unpaved, path, unknown) from BRouter's way tags; a bar under the profile and an optional coloured layer. [Details](docs/implementation.md#surface-of-the-route).
- **User position**: `LocationStore` behind the `GEOLOCATION` token; kept in memory, never stored or sent to the API. [Details](docs/implementation.md#user-position).
- **GPX import**: `parseGpx` reads a track or a route on the device; without elevation the climb stays unknown and sharing is off. [Details](docs/implementation.md#gpx-import).
- **Relief**: API `POST /elevation` over Copernicus GLO-30 tiles (`relief/`), used only to compute the climb of an imported route. [Details](docs/implementation.md#relief).
- **Credits**: `PlannedRoute.elevationSource` (`srtm` or `copernicus`) is saved with the route and credited under the profile. [Details](docs/implementation.md#credits).
- **Local storage**: Saved routes live in IndexedDB behind `ROUTE_STORE` (`RouteStore`): one itinerary, `schemaVersion`, optional `loop` and `laps`; opening one never computes. [Details](docs/implementation.md#local-storage).
- **GPX and FIT export**: `buildGpx` and `buildFit` build the file on the device from the stored geometry (the laps of a loop repeated); download through `FILE_DOWNLOADER`. [Details](docs/implementation.md#gpx-and-fit-export).
- **Offline**: A service worker (production build) plus offline areas: the corridor of a route or the view, kept as byte ranges in one cache per area (`core/offline`). [Details](docs/implementation.md#offline).
- **Saved routes list**: The whole card opens a route (with a confirmation when the one on screen is unsaved work), hovering previews it, steps are reordered by pointer or keys, names are proposed from the places. [Details](docs/implementation.md#saved-routes-list).
- **Sharing**: `PUT /p/{id}` creates an immutable shared route and returns a delete token; the share button is hidden for now (`SHARING_ENABLED`). [Details](docs/implementation.md#sharing).
- **About**: The "i" window of the header: what the app is, what goes where, code and credits, the version (the deploy tag), the Liberapay link (`ABOUT_LINKS`, also in the header); a welcome screen on the first visit. [Details](docs/implementation.md#about).
- **Design**: Direction "C3 Dossard", light theme only; tokens in `apps/web/src/design-tokens.css`, map colours in `core/map/palette.ts` (a test keeps both in step). [Details](docs/implementation.md#design).
- **Production**: https://voielibre.app on a VPS, Docker Compose behind Caddy (one origin: the web app, `/api`, `/tiles`; only Caddy publishes ports), deployed by `.github/workflows/deploy.yml` on a `v*` tag or by `scripts/deploy.sh`. The server's address and keys never go in the repository. [Details](docs/features/deploy.md).
- **Data**: PostgreSQL + PostGIS. Migrations with node-pg-migrate in `apps/api/migrations` (SQL files).
- **Routing**: BRouter behind the `RoutingProvider` interface (`apps/api/src/routing`). BRouter kills a running request when more than its thread count arrive at once, so `BRouterProvider` queues its calls (`BROUTER_MAX_CONCURRENT`); an alternative the engine cannot find is left out, an error comes only when there is no route at all. GraphHopper may come later for loops. External components (routing, geocoding, tiles, relief) always sit behind interfaces.
- **Monorepo**: Nx (integrated mode) with npm. Shared code in `libs/shared`; path aliases in `tsconfig.base.json`.

## Rules

- Code, comments, commits, docs and README in English. UI in English by default with a French translation.
- **No hard-coded UI string.** Every label goes through Transloco keys in `apps/web/public/i18n/en.json` and `fr.json`; a test fails when a key is missing in one of them. Numbers, dates and units go through the `Intl`-based formatting layer (metric by default).
- **No secret in the repository.** Configuration comes from environment variables; `.env.example` lists them all with development defaults only.
- The API returns stable error codes; the web app translates them. Validate requests and responses with schemas.
- Small verified steps: follow the plan of the work in hand (the `## Plan` section of its file in `docs/features/`; once the work is done the plan is folded into `## How it went`), commit once per step in English with a conventional message (`feat:`, `chore:`, `docs:`) after lint, build and targeted tests pass.
- Documentation moves with the code: when a feature changes, update its section in `docs/implementation.md` and keep its summary here to one line (the long text lives there, not here).
- Out of scope for milestone 1: accounts and sync, avoid zones and reports, Android APK.

## Commands

```bash
./scripts/download-segments.sh && ./scripts/download-basemap.sh && ./scripts/download-relief.sh   # once: routing data, basemap, terrain
npm run build-relief        # once, after download-relief.sh: the map's hillshade tiles (data/basemap/relief.pmtiles)
docker compose up -d        # PostgreSQL/PostGIS, BRouter, tiles server
npm run db:migrate          # apply migrations
npm run dev                 # API on :3000 and web on :4200
npm run build | test | lint # every project
npm run generate-client     # regenerate packages/api-client
```

Tests: while iterating, run only the project and file you changed (for example `npx nx test api -- brouter`, or `npx nx test web --include='**/app.spec.ts'`). Run the whole suite once at the end (`npm test`). CI runs lint, build, tests, and fails if regenerating the client leaves a diff.
