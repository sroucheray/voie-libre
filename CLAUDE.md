# Voie Libre: context for Claude Code

Read this file, [BRIEF.md](BRIEF.md) and [PLAN.md](PLAN.md) at the start of each session. Architecture lives in [docs/architecture.md](docs/architecture.md).

## What this is

Open-source (AGPL-3.0) route planner for road/gravel cycling and trail running, as a website and later an Android app (Capacitor). Local first: routes live on the device; sending anything to the server is always the user's choice. At launch the only user is the author.

## Stack (fixed)

- **Front** (`apps/web`): Angular single-page app, no SSR, strict TypeScript, standalone components, signals. MapLibre GL JS used directly. Transloco for i18n at runtime.
- **API** (`apps/api`): Node.js, Fastify, TypeScript. TypeBox schemas with `@fastify/type-provider-typebox`; OpenAPI generated by `@fastify/swagger` (spec on `/openapi.json`, UI on `/docs`). `@fastify/rate-limit` and `@fastify/cors` are registered.
- **Client** (`packages/api-client`): TypeScript types and `openapi-fetch` client generated from `/openapi.json`. Never edit `src/schema.d.ts` or `openapi.json` by hand: run `npm run generate-client`.
- **Map**: `MapView` (`apps/web/src/app/core/map`) uses MapLibre directly, lazy-loaded. The basemap (PMTiles, fonts, sprites in `data/basemap`) is served locally by the `tiles` compose service; the map must never call an external domain. Map controls and attribution are Angular elements so they are translated.
- **Planner** (`apps/web/src/app/planner`): `PlannerStore` holds the state and the pure rules (points, profile, alternatives, result); `RoutePlanner` recomputes through the generated client with a debounce and aborts stale requests; a `PlannerMapDriver` draws markers and routes (real one in `maplibre-driver.ts`, fake in tests). API error codes are translated under `planner.errors.*`; never show a raw API message.
- **Elevation profile** (`apps/web/src/app/planner/elevation-profile.ts`, `elevation-panel.*`): `buildProfile` (pure: cumulative distance, grade over a 50 m window) and `ElevationPanel` under the map. The shared cursor is `PlannerStore.cursor` (index in the selected geometry): the panel sets it on pointer or keys, `Planner` sets it from `PlannerMapDriver.onHoverRoute`, and an effect shows it as a dot through `setCursor`.
- **GPX import** (`apps/web/src/app/import/gpx-import.ts`, button in `saved-routes`): `parseGpx` (DOMParser, `querySelectorAll`: live collections are quadratic in jsdom) reads the first `<trk>` (segments joined) else the first `<rte>`; geometry thinned to 5000 points, climb with a 3 m threshold, duration estimated per profile. No elevation on every point → `ascentMeters: null` (type `number | null` on `PlannedRoute`/`SavedRoute`): the profile is hidden, sharing is disabled, `buildGpx` gets `withElevation: false`. Errors are `GpxImportError` codes translated under `gpxImport.errors.*`.
- **Relief** (API `relief/`, `routes/elevation.ts`; web `relief/elevation.service.ts`): `ElevationProvider` interface, `CopernicusElevationProvider` reads Copernicus GLO-30 GeoTIFFs from `RELIEF_DIR` with `geotiff` (one window read per tile, bilinear, `null` outside the tiles or on no-data). `POST /elevation` (max 5000 points, `ELEVATION_RATE_LIMIT_MAX`). The web app calls it only when the user asks to compute the climb of an imported route (`ElevationService.forGeometry`, gaps interpolated, refused under 80% coverage); `RouteStore.setElevation` stores the result. Jest transforms the ESM-only dependencies of `geotiff` (see `jest.config.cts`). The real-data spec skips itself without the tiles.
- **Credits**: `PlannedRoute.elevationSource` (`'srtm'` for BRouter routes, `'copernicus'` once the climb was computed from tiles; absent for an imported file's own elevations) is stored with the saved route and shown under the profile (`profile.source.*`).
- **Local storage** (`apps/web/src/app/storage`, `saved-routes`): saved routes live in IndexedDB (native API) behind the `RouteStore` interface, injected with the `ROUTE_STORE` token (SQLite can replace it under Capacitor). Only the selected itinerary is stored, with a `schemaVersion`; ids are 10 random characters. Opening one goes through `PlannerStore.loadSaved`, which must never trigger `POST /route` (`RoutePlanner` skips inputs matching the restored route until the user edits). Storage failures are `RouteStoreError` codes translated under `saved.errors.*`; the planner stays usable without storage.
- **GPX export** (`apps/web/src/app/export`): `buildGpx` (pure, GPX 1.1, one `<wpt>` per route point with translated names, then one track) turns a saved route's stored geometry into a file on the device; the download goes through the `FILE_DOWNLOADER` token (browser link now, Capacitor share later). Never built by the API.
- **Offline** (`apps/web/src/app/core/offline`, `ngsw-config.json`): `@angular/service-worker` (production build only) prefetches the app shell and the i18n files, and keeps the basemap's glyphs and sprites (`dataGroups`, matched on any host by the `/fonts/**` and `/sprites/**` patterns of `ngsw-config.json`). The PMTiles archive is downloaded on demand by `OfflineBasemap` into Cache Storage and read by byte ranges through `OfflineFirstSource` (offline copy first, HTTP range requests otherwise), so the map never needs the network once downloaded. Check offline with `npm run serve:prod` (`scripts/serve-static.mjs`: static files with an `index.html` fallback; the service worker does not run in `npm run dev`). When the network cannot carry a request, the service worker answers 504: the API error mappers treat 504 as network/unavailable.
- **Sharing** (API `routes/shared.ts`, `db/shared-routes.ts`; web `sharing/`): no account. `PUT /p/{id}` creates a shared route under the id drawn on the device and returns a delete token once (only its SHA-256 is stored); shared routes are **immutable** (an existing id answers 409, no update); `GET /p/{id}`, `GET /p/{id}.gpx?lang=`, `DELETE /p/{id}` with `Authorization: Bearer <token>`. PUT is throttled hard (`SHARE_RATE_LIMIT_*`) and capped (`SHARE_BODY_LIMIT_BYTES`, 5000 geometry points, 20 points). The token stays in the local record (`SavedRoute.share`), never in a URL or on screen. Sharing is always an explicit user action; deleting a shared route unshares it first. `/p/:id` in the web app (`SharedRoutePage`) opens a link through `PlannerStore.loadSaved`, without computing or storing. GPX building and the id alphabet live in `libs/shared` (used by both).
- **Data**: PostgreSQL + PostGIS. Migrations with node-pg-migrate in `apps/api/migrations` (SQL files).
- **Routing**: BRouter behind the `RoutingProvider` interface (`apps/api/src/routing`). GraphHopper may come later for loops. External components (routing, geocoding, tiles, relief) always sit behind interfaces.
- **Monorepo**: Nx (integrated mode) with npm. Shared code in `libs/shared`; path aliases in `tsconfig.base.json`.

## Rules

- Code, comments, commits, docs and README in English. UI in English by default with a French translation.
- **No hard-coded UI string.** Every label goes through Transloco keys in `apps/web/public/i18n/en.json` and `fr.json`; a test fails when a key is missing in one of them. Numbers, dates and units go through the `Intl`-based formatting layer (metric by default).
- **No secret in the repository.** Configuration comes from environment variables; `.env.example` lists them all with development defaults only.
- The API returns stable error codes; the web app translates them. Validate requests and responses with schemas.
- Small verified steps: follow PLAN.md, commit once per step in English with a conventional message (`feat:`, `chore:`, `docs:`) after lint, build and targeted tests pass.
- Out of scope for milestone 1: accounts and sync, avoid zones and reports, Android APK.

## Commands

```bash
./scripts/download-segments.sh && ./scripts/download-basemap.sh && ./scripts/download-relief.sh   # once: routing data, basemap, terrain
docker compose up -d        # PostgreSQL/PostGIS, BRouter, tiles server
npm run db:migrate          # apply migrations
npm run dev                 # API on :3000 and web on :4200
npm run build | test | lint # every project
npm run generate-client     # regenerate packages/api-client
```

Tests: while iterating, run only the project and file you changed (for example `npx nx test api -- brouter`, or `npx nx test web --include='**/app.spec.ts'`). Run the whole suite once at the end (`npm test`). CI runs lint, build, tests, and fails if regenerating the client leaves a diff.
