# Plan — stops anywhere and a descriptive profile choice

Brief: [BRIEF-panel-stops-profile.md](BRIEF-panel-stops-profile.md). Each step ends with lint, build and targeted tests passing, then one commit. One full run at the end.

1. **"+" between the fields.** In `Planner`: `newStopOpen` (boolean) becomes `newStopAt` (`number | null`, the index the new stop will take, 1 to `points.length - 1`); the list of stops is always rendered once there are two points, with a "+" button before each stop and before the end (`planner.stops.addHere`, with the names of the two neighbours for screen readers) and the empty field at `newStopAt`. `pickNewStop` and the `'new'` position target insert at that index. The "Add a stop" button, `addStop()` and the `planner.stops.add` key go. `newStopAt` is dropped when the points change under it (undo, removal, clear). Styles: a small round button on the line between two fields, 24 px touch target at least. Check: `planner.spec.ts`.
2. **Reorder handle on the left.** In the stops list of `Planner`, the draggable `.point-grip` moves before `vl-place-field` and shows the grip dots and the stop's number; `PlaceField` gets a `bareMarker` input that hides its own number marker for these rows (the empty new-stop field keeps its marker). Styles: handle at least 32 px wide and high, aligned with the markers of the start and end fields; the remove button alone on the right. Check: `planner.spec.ts`, `place-field.spec.ts`.
3. **Profile dropdown.** New standalone `ProfileSelect` (`apps/web/src/app/planner/profile-select.*`): inputs `value` and `profiles`, output `changed`; select-only combobox (button `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`; `listbox` of `option`s with title and description), keys and outside click as in the brief. Keys `planner.profile.<id>.title` and `.description` replace `planner.profile.<id>` in both languages (other uses of the old keys updated). `Planner` uses it in place of the radio fieldset; the undo/redo key handler ignores it. Check: `profile-select.spec.ts`, `planner.spec.ts`, the i18n key test.
4. **Visual check and docs.** Chromium as in the brief (English, French, phone width). `CLAUDE.md` (place search bullet for the "+", one line for the dropdown) and `docs/architecture.md` if it names the radio buttons or the button. Full run once (`npm test`), lint and build.
