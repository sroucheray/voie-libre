# Plan — milestone 1 (foundation)

Each step ends with the project starting and its tests passing. Targeted tests during a step; one full run at the end.

1. **Repo skeleton.** Nx workspace, `apps/web` (Angular, strict), `apps/api` (Fastify), shared lib for types. AGPL `LICENSE`, `README.md`, `.env.example`, `.gitignore`. Check: both apps build and start; empty test suites run.
2. **i18n and formatting.** Transloco with `en.json` then `fr.json`, language switch, formatting service on `Intl` (distance, elevation, dates; metric). Check: unit tests for the formatter; a missing-key check between `en.json` and `fr.json`.
3. **Dev infrastructure.** `docker-compose.yml` with BRouter (segment `E0_N45` for the Clermont-Ferrand test region, downloaded by a script, not committed; start from `spike/brouter/start.sh`, 512 MiB container) and PostGIS. Check: `GET /brouter` answers a route between two points. The spike showed `avoid` zones and alternatives work (see `spike/brouter/RAPPORT.md`).
4. **Routing provider interface (API).** `RoutingProvider` interface and BRouter adapter (points, profile, alternatives to geometry + distance, ascent, duration). `POST /route` with Fastify schemas. Check: adapter unit tests against recorded BRouter responses; one integration test against local BRouter.
5. **OpenAPI and generated client.** `@fastify/swagger` spec, generation of the TypeScript client into the shared lib, wired into the web app. Check: regenerating the client leaves no diff.
6. **Map and planner.** MapLibre component (PMTiles source), click to set start, end and waypoints, profile selector (road, gravel, trail), route drawn from `POST /route`, alternatives shown. All labels through Transloco. Check: component tests for planner state; manual check in the browser.
7. **Local storage.** `RouteStore` interface with an IndexedDB implementation: save, list, open, delete. Short ids (8–10 random chars). Check: unit tests with a fake IndexedDB.
8. **GPX export.** Generate GPX from stored geometry on the device and download it. Check: unit tests on output; validate in a GPX viewer.
9. **Offline.** Service worker and PWA manifest, offline PMTiles extract for the test region, open a saved route with no network. Check: manual offline test (devtools network off).
10. **Sharing without account.** `PUT /p/{id}`, `GET /p/{id}`, `GET /p/{id}.gpx`; link and QR code on the web app. Check: API tests; open a shared link in a second browser profile.
    10a. **Elevation profile** (added). Chart of distance against elevation under the map, from the selected route's stored geometry; hovering it (or arrow keys) moves a dot on the map, hovering the route on the map moves the cursor on the chart; collapsible; grade in the tooltip, no colouring yet. Check: unit tests; manual check on a saved route.
    10b. **GPX import** (added, done). `<trk>` first, `<rte>` as a fallback; saved as a local route without calling `POST /route`; no elevation → imported with an unknown climb (profile hidden, sharing disabled); the "compute the climb?" question comes with 10c, once the relief service exists.
    10c. **Relief service** (added, done). `ElevationProvider` interface in the API and an endpoint that returns elevations for points; used by the import's "compute climb" choice.
11. **Wrap-up** (done). Full test run once, README quick start, update `docs/architecture.md` if anything diverged.

## Backlog (noted 2026-11-08, not started)

- **Bug: map tiles not always refreshed after moving the map.** Some tiles stay stale or missing after a pan. Reproduce, then check the PMTiles source (`OfflineFirstSource`, range requests, caching) and the MapLibre tile cache.
- **Feature: add a stop between A and B by address.** A search field per stop, like Start and End (`PlaceField`), with its own place in the list of stops; the stops list stays reorderable. Today stops are added by click or menu only (`BRIEF-search.md` left it out of scope).
- **Bug: three alternatives return nothing.** From 30 rue Francis de Pressensé (Clermont-Ferrand) to Pavezin (Loire, France), asking for 3 alternatives shows an error ("trips could not be computed") and no route; 1 or 2 alternatives work. Reproduce against the local BRouter (`POST /route` with `alternatives: 3`), find whether BRouter fails on the third alternative (then return the ones found instead of failing the whole request) or the API or timeout does.
- **Feature: select a stretch of the elevation profile.** Dragging over the chart selects a portion and shows its distance and the climb done over it (ascent, and descent), possibly with the average grade. To decide: colours by difficulty (grade bands) on the profile, and maybe on the route line on the map (to be seen). Builds on `buildProfile` (`elevation-profile.ts`, grade over a 50 m window) and `ElevationPanel`; the selection could be highlighted on the map through `PlannerMapDriver`.
- **Feature: use my current location as the start or the end from the fields.** A "My position" choice in the Start and End fields (for instance an entry in the suggestions, or a button beside each field) that sets that point from the device position. Reuses `LocationStore` and the "My position" logic of the panel and map menu (`addPoint` at the fix), but targets the start or the end explicitly (`setStart`/`setEnd`); the position stays in memory and is never stored or sent, except the address lookup the fields already do for their points.
- **Feature: preferred direction for a loop.** When a loop is computed (by distance, and possibly the other modes), let the user pick a preferred direction: north, north-east, east, and so on (8 compass points, or none). For a loop by distance the engine already tries evenly spaced directions (`BRouterProvider.roundTrip`, `ASCENT_DIRECTIONS`), so the preferred one could set the direction of the first candidate or the one favoured among them. Needs a field in `loop: {mode: 'distance', ...}` (schema, generated client), a control in the loop dialog and the panel, and translations (`planner.loop.*`).
- **Feature: drag a point of the trace with live recomputation.** Dragging a point (marker, or the route line to insert one) recomputes the route while the pointer moves, not only on release. Open question: how to cancel a move the user no longer wants. Ideas to weigh: Escape during the drag puts the point back and restores the route on screen; releasing outside the map or on the original spot cancels; after the drop, the existing undo (Ctrl/Cmd+Z, `PlannerStore` snapshots) already reverts it, and a drag should push a single snapshot, not one per recomputation. Design points: throttle or debounce the live calls and abort stale ones (`RoutePlanner` already aborts), keep the previous route on screen until the new one arrives, prefer the local edit (`planLocalEdit`, a short `POST /route` around the point) so each step stays cheap and BRouter is not flooded, and respect the route rate limit (`ROUTE_RATE_LIMIT_MAX`). The preview during the drag must not enter the history nor the saved route until the drop.
